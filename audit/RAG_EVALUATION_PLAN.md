# Reproducible RAG evaluation plan

## Fixed dataset and labels

Use the three version-pinned papers and checksums in [sources.json](../evaluation/sources.json) for development and regression. First reproduce the abstract-only pilot using the existing [runner](../evaluation/run.py) and [scorer](../evaluation/score.py). Keep its results separate from full-paper estimates. For the new experiment, freeze a manifest of locally collected full PDFs and held-out documents spanning automotive/systems and at least one other area. Target 20 held-out papers if reviewer time permits. Record exact PDF versions, SHA-256, licences, and extraction and chunking profiles. Split by paper and publication family before tuning. Include numerical and multi-span items, explicit limitations, answerable paraphrases, exact identifiers and genuinely unanswerable field requests. Record unreadable or image-only evidence as an extraction failure stratum.

Freeze a task set of field requests and reference atomic facts per paper, including expected units, baselines and qualifiers. Label all acceptable evidence alternatives in extracted PDF page coordinates, including multi-span requirements. Use two reviewers to annotate independently and adjudicate disagreements. Freeze the reference set before scoring system outputs. Review pooled candidate spans blind to retrieval strategy to identify missing valid alternatives, then adjudicate and freeze those labels before reporting. Keep development and held-out adjudication logs separate. Use paper checksum, physical page and character range as stable labels across indexes. Write material overlap and sufficiency rules before scoring.

## Paired experiment arms

| Arm | Intervention and purpose |
| --- | --- |
| A. Existing no-index baseline | Use the shipped direct text FAST spread-sampling behavior and baseline prompts with full-paper input. Add the shipped FULL pipeline as a descriptive coverage/cost comparator, since its map calls and context differ. |
| B. Existing retrieval | Replay the shipped FAST selector, including fixed query, fallbacks, reranking and page diversity, with baseline prompts. Also record one shipped active prompt configuration as the deployment reference. |
| C. Improved retrieval | Compare document-scoped field-aware BM25, existing local semantic retrieval, and deterministic reciprocal rank fusion. Hold field queries, generator, packing rules, context and output budgets constant across these variants. Keep the original selector intact for B. Report a lexical run with the same fixed query under the improved selector to distinguish query effects where practical. |
| D. Advanced prompting | With B and the selected C winner, replay identical packed evidence with baseline, fields, and evidence-first prompts for each specialist. Use fixed summary input for isolated question scoring. Then run the cross-stage selected prompt configuration end to end. Evaluate new typed evidence prompts under a common output contract across variants to separate format effects. |
| E. Validation and correction | Freeze retrieval and prompts from D. Compare draft-only, checks-only, one revision with original context, and gap-triggered retrieval plus one revision. The last pair isolates the value of new context. Report results over all cases and separately over cases that triggered follow-up. |

Tune query lists, retrieval depths, fusion and prompt choices on development papers. Evaluate all predeclared arms once on held-out labels, with the deployment choice based on development results and the agreed acceptance gates. Run retrieval-only comparisons on identical ranked-list cutoffs such as 5, 10 and 20. Score generation separately under the same actual evidence and output budgets where possible. For retrieval scoring, a no-index baseline can be scored as a set of delivered excerpts, with ranking metrics omitted if no ranking was produced.

## Measurements

| Metric | Operational definition |
| --- | --- |
| Retrieval precision and recall | Precision@k = distinct relevant retrieved units divided by returned units up to k, with duplicate spans receiving no extra credit. Recall@k = distinct gold evidence requirements covered divided by all applicable requirements, treating alternative sources as equivalents and separately reporting jointly satisfied multi-span requirements. Score both candidate ranks and packed excerpts. Report unanswerable items and zero-hit cases explicitly. |
| Scientific factual accuracy | Correct atomic claims divided by all verifiable generated claims, checked against the full paper with units, magnitude, direction, study conditions and attribution. |
| Extraction completeness | Correctly extracted applicable gold facts divided by all applicable gold facts. Score missing fields, abstentions and wrong values separately. |
| Citation correctness | Correctly resolving and supporting claim-to-span references divided by emitted references. Also report cited-claim coverage over factual claims and distinguish resolution from support. Report precision as undefined when no citations are emitted. |
| Evidence relevance | Review packed excerpts on a preregistered 0/1/2 scale for unrelated, contextually helpful, or directly supporting a target. Report direct-support fraction and grades per field. |
| Unsupported claim rate | Claims not justified by supplied evidence divided by factual claims, even if the source elsewhere happens to support them. Count unverifiable and contradicted claims separately. Score final and draft versions. |
| Research-question usefulness | Two blinded reviewers score specificity, grounding, feasibility and novelty relative to the supplied evidence on 0–2 scales with written anchors and adjudication. Report useful fraction using a frozen threshold, category accuracy, and agreement. Full literature novelty remains outside title-only evidence. |
| Execution latency | Wall-clock end-to-end and per stage, median and p95, with failures and timeouts reported. Separate cold indexing, warmed retrieval, generation, validation and revision costs. Record CPU/GPU settings, token counts, query and model call counts, and index sizes. |

## Reproduction and analysis

Pin commit, dependencies, Windows/Ollama versions, local generation and embedding model digests, model parameters and seed when supported, PDF and index profiles, prompt fingerprints, and budgets. Disable response cache and use fresh per-arm summary journals in quality and latency runs. Reuse one immutable, verified index snapshot for warm comparisons and rebuild under a separate cold protocol. Use real local inference, constant hardware and rotated execution order with three repetitions for timing where feasible. Record repeats and match inputs. Freeze OpenAlex responses or disable the discovery stage consistently for core extraction latency, then run a separate live MCP compatibility smoke. Include no-answer and failure cases in denominators or explicitly report attrition. Never transfer review labels to changed outputs. Existing repeat-review verification already checks evidence, model configuration, and output identity. [Repeat checker](../evaluation/compare_repeat.py), [execution report](../evaluation/EXECUTION_REPORT.md)

Aggregate per paper, report paired differences and paper-cluster bootstrap intervals, and show counts, reviewer agreement and failure examples. Use macro as primary and pooled micro as supplemental. Compare quality and cost jointly. Pre-register minimum worthwhile effects on development data before opening held-out results. Proposed discussion thresholds are a five percentage point increase in packed evidence recall with no more than a two point precision loss, and a five point drop in unsupported claims with no more than a two point completeness loss. Set a local p95 budget with the supervisor and report total indexing cost. Keep the simpler method when intervals are inconclusive or gains fail the quality/cost gates. For Agentic RAG, also require at least one traced, correctly resolved evidence gap on held-out papers and report follow-up benefit, false triggers and stop behavior across the cohort.
