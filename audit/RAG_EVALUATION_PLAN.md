# Reproducible RAG evaluation plan

## Fixed dataset and labels

Use the three version-pinned papers and checksums in [sources.json](../evaluation/sources.json) for development and regression. First reproduce the abstract-only pilot using the existing [runner](../evaluation/run.py) and [scorer](../evaluation/score.py). Keep its results separate from full-paper estimates. For the new experiment, freeze a manifest of locally collected full PDFs and held-out documents spanning automotive/systems and at least one other area. Target 20 held-out papers if reviewer time permits. Record exact PDF versions, SHA-256, licences, and extraction and chunking profiles. Split by paper and publication family before tuning. Include numerical and multi-span items, explicit limitations, answerable paraphrases, exact identifiers and genuinely unanswerable field requests. Record unreadable or image-only evidence as an extraction failure stratum.

Freeze a task set of field requests and reference atomic facts per paper, including expected units, baselines and qualifiers. Label all acceptable evidence alternatives in extracted PDF page coordinates, including multi-span requirements. Use two reviewers to annotate independently and adjudicate disagreements. Freeze the reference set before scoring system outputs. Review pooled candidate spans blind to retrieval strategy to identify missing valid alternatives, then adjudicate and freeze those labels before reporting. Keep development and held-out adjudication logs separate. Use paper checksum, physical page and character range as stable labels across indexes. Write material overlap and sufficiency rules before scoring.

## Paired experiment arms

| Arm | Intervention and purpose |
| --- | --- |
| A. Existing no-index reference | Use the shipped direct-text FAST spread-sampling behavior and baseline prompts with the full-paper input. Record the shipped FULL map/reduce pipeline as a separate descriptive coverage/cost reference because its context and call count differ. |
| B. Existing RAG paths | Replay FAST's fixed-query lexical selector, including fallback, custom rerank and page diversity. Separately evaluate corpus QA's default `spans` strategy with BM25. Record corpus search's semantic and hybrid modes as already-implemented alternatives; keep identical source scope and final context budget. |
| C. Improved retrieval | Compare the existing BM25, local semantic and RRF hybrid methods to field-aware query variants and deduplication/context packing. This is an evaluation of current retrieval plus proposed policy improvements, not a plan to add embeddings or a vector database. Keep retrieval and query-generation effects separable; use the same generator, prompts, output budget and corpus snapshot. |
| D. Advanced prompting | On the same frozen evidence from B or the development-selected C method, compare baseline, fields and evidence-first prompt families. Use fixed summary input for isolated question scoring, then evaluate the selected configuration end to end. Keep output schema identical; report format validity separately from factual accuracy. |
| E. Evidence validation and correction | Compare the current one-pass `spans` QA, legacy follow-up/verification strategy, draft-only, checks-only, same-context revision, and (where independently switchable) gap-triggered retrieval plus revision. The key contrast is whether new evidence—not merely another generation—improves support. Report results on all cases and on follow-up-triggered cases; preserve a no-follow-up arm. |

Tune query lists, retrieval depths, fusion and prompt choices on development papers. Evaluate all predeclared arms once on held-out labels, with the deployment choice based only on development results and agreed gates. Run retrieval-only comparisons on identical ranked-list cutoffs such as 5, 10 and 20. Score both the retrieved candidate set and the excerpts that actually fit the prompt; score generation separately under equal actual evidence/output budgets wherever possible. A no-index baseline can be scored as a set of delivered excerpts, with ranking metrics omitted when no ranking was produced. Exercise the legacy strategy through its internal Python API for diagnosis first; do not claim its behavior is available to normal MCP/Streamlit consumers until a later approved change exposes it.

## Measurements

| Metric | Operational definition |
| --- | --- |
| Retrieval precision and recall | Precision@k = distinct relevant retrieved units divided by returned units up to k, with duplicate spans receiving no extra credit. Recall@k = distinct gold evidence requirements covered divided by all applicable requirements, treating alternative sources as equivalents and separately reporting jointly satisfied multi-span requirements. Score both candidate ranks and packed excerpts. Report unanswerable items and zero-hit cases explicitly. |
| Scientific factual accuracy | Correct atomic claims divided by all verifiable generated claims, checked against the full paper with units, magnitude, direction, study conditions and attribution. |
| Extraction completeness | Correctly extracted applicable gold facts divided by all applicable gold facts. Score missing fields, abstentions and wrong values separately. |
| Citation correctness | Correctly resolving and supporting claim-to-span references divided by emitted references. Also report cited-claim coverage over factual claims and distinguish resolution from support. Report precision as undefined when no citations are emitted. |
| Evidence relevance | Review packed excerpts on a preregistered 0/1/2 scale for unrelated, contextually helpful, or directly supporting a target. Report direct-support fraction and grades per field. |
| Unsupported claim rate | Claims not justified by supplied evidence divided by factual claims, even if the source elsewhere happens to support them. Count unverifiable and contradicted claims separately. Score final and draft versions. |
| Research-question usefulness | Two blinded reviewers score specificity, grounding, feasibility and novelty relative to the supplied evidence on 0–2 scales with written anchors and adjudication. Report useful fraction using a frozen threshold, category accuracy, and agreement. Full literature novelty remains outside title-only evidence. |
| Execution latency | Wall-clock end-to-end and per stage, median and p95, with failures and timeouts reported. Separate cold indexing, warmed retrieval, generation, validation and revision costs. Record CPU/GPU settings, token counts, query and model call counts, and index sizes. |

## Reproduction and analysis

Pin commit, dependencies, Windows/Ollama versions, generation and embedding model digests, model parameters and seed when supported, PDF/index profiles, prompt fingerprints, retrieval mode, QA strategy and budgets. Disable response cache and use fresh per-arm summary journals in quality and latency runs. Reuse one immutable, verified index snapshot for warm comparisons and rebuild under a separate cold protocol. Use real local inference, constant hardware and rotated execution order with three repetitions for timing where feasible. Record repeats and match inputs. Freeze OpenAlex responses or disable discovery consistently for core manuscript-evidence latency, then run a separate live MCP compatibility smoke. Include no-answer and failure cases in denominators or explicitly report attrition. Never transfer review labels to changed outputs. Existing repeat-review verification checks evidence, model configuration and output identity. [Repeat checker](../evaluation/compare_repeat.py), [execution report](../evaluation/EXECUTION_REPORT.md)

Aggregate per paper, report paired differences and paper-cluster bootstrap intervals, and show counts, reviewer agreement and failure examples. Use macro as primary and pooled micro as supplemental. Compare quality and cost jointly. Pre-register minimum worthwhile effects on development data before opening held-out results. Proposed discussion thresholds are a five percentage point increase in packed evidence recall with no more than a two point precision loss, and a five point drop in unsupported claims with no more than a two point completeness loss. Set a local p95 budget with the supervisor and report embedding/index cost. Keep the simpler method when intervals are inconclusive or gains fail the quality/cost gates. For Agentic RAG, require traces where a correctly identified evidence gap changes the retrieved set and improves a supported outcome on held-out papers; also report false triggers, duplicate/no-hit follow-ups, budget stops and unresolved cases. A single successful trace proves only that the code path executed, not that it reliably improves answers.

The current Q&A tests use synthetic documents and controlled fake models to exercise exact offsets, prompt-injection rejection, follow-up, numeric rejection and a verifier path. They are valuable regression tests, not scientific-quality measurements. Existing prompt results are a separate three-abstract pilot: baseline/fields/evidence summary reference recall was 7/18, 11/18 and 9/18, while all question strategies scored 0/3 for complete useful research questions and title-only relevance remained weak. Reuse those findings as historical motivation, not as RAG retrieval evidence.
