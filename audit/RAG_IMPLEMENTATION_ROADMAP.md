# RAG implementation roadmap

Application changes begin only after roadmap approval. Each stage preserves the existing agents, local Ollama path, MCP stdio contracts, and current FAST/FULL modes. BM25, local semantic retrieval, RRF hybrid search, exact-span CorpusQA, and one bounded internal follow-up strategy already exist; the roadmap measures and integrates them rather than rebuilding them.

| Stage | Work | Exit evidence |
| --- | --- | --- |
| 0. Freeze the actual baseline | Capture current FAST/FULL, standalone MCP, corpus search and default `spans` Q&A behavior, active prompts, model/index fingerprints, and existing reports. Resolve historical report-count differences and agree on a held-out corpus, labels and thresholds. | Reproducible configs and a frozen paper/question/span manifest. Separate source inspection and saved evidence from newly executed tests. |
| 1. Measure existing retrieval and context | Compare shipped FAST fixed-query BM25, corpus BM25, corpus semantic and existing hybrid RRF at matched candidate/final context sizes. Measure current query selection, fallback and passage packing; scope all retrieval to the authorized document set. | Judged retrieval and packed-context scores, page-span round trips, and cold/warm latency show which specific gap warrants a change. |
| 2. Select retrieval policy (conditional) | If the benchmark justifies it, tune field-aware query construction, overlap deduplication and deterministic context packing. Reuse existing local vector index and hybrid method; keep the simplest winner and preserve the original FAST path for comparison. | Held-out evidence recall/relevance and latency pass pre-agreed gates. No new vector database or semantic default absent measured value. |
| 3. Integrate and evaluate structured answers | Reuse CorpusQA's exact-span contracts and Markdown variants. Where users need richer extraction, add typed claim/value/unit/qualifier/citation/status fields only after defining the consumer contract. Keep `analyze_paper` output compatible. | Claim-level factual accuracy, completeness, citation resolution/support and prompt effects are scored on identical frozen evidence. Existing agent and MCP contracts remain covered. |
| 4. Expose bounded Agentic RAG (conditional) | Compare the current one-pass `spans` path with legacy follow-up, checks-only, same-context revision and retrieval-plus-revision. If effective, expose a versioned opt-in strategy in UI/MCP; retain controller-owned scope, shared time/call budgets, trace, and explicit unresolved status. | Held-out traces show new evidence resolving real gaps at acceptable benefit/cost; tests cover repeated queries, no hits, unsupported claims, false triggers, timeout, cancellation and authorization. |
| 5. Verify integration and publish | Run focused/full tests after application approval. Use real local Ollama, the current stdio client and Streamlit smoke tests; verify checksums, stable page spans, saved-result reload and compatibility of all current tools. Publish commands, raw results, metrics and deviations. | Current UI/MCP strategy options behave as documented, results are reproducible, and all eleven source-declared tool contracts remain intact. |

Reuse [prior execution evidence](../evaluation/EXECUTION_REPORT.md) for historical comparisons and [the evaluation plan](RAG_EVALUATION_PLAN.md) for new measurements. Defer OCR, specialized table parsing or broader infrastructure until measured evidence gaps warrant them.

## Final verdict

1. **Is the current system already RAG?** Yes. The FAST Orchestrator retrieves BM25-ranked PDF passages before generation; the corpus also supports separate semantic and hybrid retrieval, plus question-conditioned corpus QA. FULL and direct standalone-agent paths are different. [Assessment](RAG_ARCHITECTURE_ASSESSMENT.md)
2. **Is it already Agentic RAG?** Not as the default project workflow. `CorpusQA(strategy="legacy")` contains a bounded model-proposed follow-up retrieval and verification/revision behavior, but current UI and MCP callers use `spans` and cannot select it; the four-agent Orchestrator is fixed. Call it a RAG application with an internal Agentic RAG prototype. [Gap analysis](AGENTIC_RAG_GAP_ANALYSIS.md)
3. **What is missing?** The main agents lack task-specific retrieval requests and claim-level evidence links; retrieval and answer quality have no held-out gold evaluation; the adaptive QA strategy is not exposed as a user-selectable path. Metadata for imported papers is operator-supplied. Existing lexical/semantic/hybrid methods and exact-span QA should be reused, not duplicated. [Target architecture](TARGET_ARCHITECTURE.md)
4. **What should be implemented next?** First freeze/evaluate the current retrievers and QA modes. After approval, improve only a demonstrated gap, then (if the measured legacy loop helps) expose it behind an explicit bounded UI/MCP option without changing existing contracts.
5. **How can improvement be demonstrated?** Compare paired full-paper/query cases with identical documents, model, prompts, evidence budgets and corpus snapshots. Blindly adjudicate retrieval, claim support, citations, completeness and question usefulness; ablate prompting, validation, same-context revision and new-evidence follow-up. Report uncertainty, latency, failures, false triggers and raw traces. [Evaluation plan](RAG_EVALUATION_PLAN.md)

The named Google whitepaper was not available for verification during this assessment; this roadmap does not attribute requirements or findings to it.
